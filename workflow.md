The Worklfow

I am gonna working on this problem through iterations.
Every iteration produces a deliverable, adding more functionality to the previous ones.

Steps would be: 
 - Defining specs based on the known functional requirements 
	- This does not have to be exhausting, since the brief isnt complete either
	- As the project develops, new specs would appear and those will be added to iterations aswell
	- Specs can be updated during development, adding more context to it
	- Every spec serves as the "source of truth" about the feature. It contains the requirements, the acceptance criteria, the implementation plan, and the verification
	- Test are generated by the acceptance criteria
 
 - Organizing specs into iterations
	- First few iterations should produce a walking skeleton that later can be extended with more functionality
	- Scope of iteration can change during development

- Giving instructions to the agent about the workflow with AGENTS.md and SKILL.md files like:
	- Summarize the task before implementing
	- Prefer TDD
	- Produce small, reviewable amount of changes
	- Do not overengineer. Prefer deciding on things in the last responsible moment
	- Ask if blocked

- Instruct the agent to start implementing the specs in order
	- Human is reviewing the changes
	- Making corrections and suggestions and adding those into skills to use them in the future
	- Asking suggestions from the agent as the project develops 
 
Workflow is subject to change. Please check git history.
